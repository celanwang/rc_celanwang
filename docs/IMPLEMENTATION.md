# API 通知系统实施与验收

## 交付目标

建设一个持久化接收、异步投递和故障后可恢复的通知服务。业务方提交已构造的 HTTP(S) 请求，服务以有效 `2xx` 响应确认投递；允许重复请求，不保证供应商业务效果恰好一次。

任务由 `notification` 保存，尝试历史由 `notification_attempt` 保存。接收提交后返回任务 ID，后台根据等待、处理中、成功、失败四种状态执行；暂时故障受控重试，自动处理停止后保留原因和重放入口。

本轮交付是文档整理。服务代码、运行环境和运行验收尚未完成；以下条件用于后续实施，不是测试通过记录。

## 建设顺序

实现按可检查的纵向流程推进。每一步交付可运行或可验证的结果，再扩展后续能力，避免先铺设大量没有执行路径的抽象。

| 阶段 | 输出 | 进入下一阶段的条件 |
|---|---|---|
| 工程基础 | Go module、配置校验、MySQL migration、API 类型和状态枚举 | 固定工具链可构建，迁移可重复执行，配置错误可定位 |
| 接收与单次投递 | 接收幂等、持久化、HTTP 外呼、任务查询 | 正常请求、同键重试、内容冲突和数据库失败用例通过 |
| 调度与恢复 | 退避、租约、条件写回、尝试历史 | 并发领取、进程崩溃、迟到写回和恢复用例通过 |
| 运行管理 | 目标隔离、地址与传输限制、重放、指标和数据清理 | 长期故障可发现、可定位、可恢复，权限与资源限制有效 |
| 提交验收 | 可复现运行说明、演示脚本、测试结果、AI 协作记录 | 必验场景有证据，运行命令实际可执行，限制明确 |

建设中只修订实际受影响的契约和文档。README 保持问题理解、架构与取舍的职责，运行步骤与验证结果由建设材料记录。

## 验证方式

Go 单元测试覆盖状态转移、错误分类、预算、退避、请求摘要和重放规则。时钟与随机源可控，边界测试不依赖实际长时间等待；非法状态转移也要有明确断言。

HTTP 测试使用 `httptest` 或可编程模拟供应商，控制响应状态、延迟、断连、TLS 和实际请求计数。供应商幂等示例另行记录业务副作用，不能仅凭通知服务的尝试计数证明外部执行次数。

MySQL 集成测试使用选定版本的真实数据库，覆盖唯一约束、行锁、事务回滚和条件更新。SQLite 或存储 Mock 不能替代这些验证。TLS 用例配置受信任测试 CA，并保留未知 CA、过期和域名不匹配等拒绝场景。

进程级测试在持久化、领取、发送和写回等边界注入故障，终止或重启进程，再联合检查任务、尝试记录与供应商日志。结果写回异常必须与外呼异常分别测试，避免将数据库重试误写成再次发送。

## 必验场景

| 场景 | 可观察的通过条件 |
|---|---|
| HTTP/HTTPS 与不同正文格式 | URL、Method、业务 Header、Body 正确，历史完整 |
| 供应商返回 `200`，正文却说明业务失败，例如“联系人不存在” | 任务标记为投递成功，不根据正文判断业务结果或触发重试 |
| 供应商返回 `202`，表示已接受请求、后续处理可能仍在排队 | 任务标记为投递成功，不等待或查询后续业务结果 |
| 并发同键提交、同键不同内容 | 只创建一条任务，冲突返回 `409`，不改变已有状态 |
| 数据库不可用或接收提交结果不明 | 不虚假确认接收，同键重试收敛到同一任务 |
| 持久化后杀进程、领取后发送前崩溃 | 重启后任务可恢复，没有永久卡住或无记录丢失 |
| 供应商执行后、成功写回前崩溃 | 可以观察重复请求；供应商幂等开启时副作用只发生一次 |
| 多 Worker 领取同一任务 | 同一有效领取周期只有一个持有者，尝试编号不冲突 |
| 成功写回与租约回收竞争 | 按事务提交顺序收敛，回收后旧令牌不能覆盖新状态 |
| 结果写回死锁或提交不明 | 恢复数据库记录，不因写回重试直接再次外呼 |
| `4xx/5xx` 未产生 Go error | 仍按响应状态正确分类 |
| 暂时失败后恢复、`Retry-After` | 退避正确；覆盖秒数、日期和无效值，不提前重试 |
| 预算耗尽、过期、重复重放 | 停止原因明确；新轮次保留历史和业务标识，陈旧操作不能再开轮次 |
| 有效期内开始、过期后返回 | 当前领取者取得的有效 `2xx` 不因过期被丢弃 |
| 证书错误、重定向和地址绕过 | 证书验证有效，无自动降级或额外目标请求，非法目标被限制 |
| 超大或缓慢响应、诊断正文失败 | 内存与时间有界，已确认的 `2xx` 不因留样失败重发 |
| 本地停机取消 | 可恢复，错误来源不被误记为供应商 |
| 单目标长期超时、积压达到水位 | 其他目标获得执行机会，拒收明确，已接收任务保留 |
| 权限隔离、凭证与日志 | 查询和重放不越权，不转发接入凭证，敏感信息不泄漏 |
| 终态清理与幂等保留 | 活动任务不删除，关联历史按约定清理，幂等窗口边界明确 |

## 实验参数

以下数值作为开发与测试起点，不是 PRD 指定参数或性能承诺。实现配置应能调整，并在每次运行证据中记录实际值。

| 参数 | 起点 |
|---|---|
| 总超时 / 连接 / TLS / 响应头 | 10 秒 / 3 秒 / 3 秒 / 5 秒 |
| 租约 / 扫描间隔 | 30 秒 / 1 秒 |
| 全局 / 单目标并发 | 20 / 4；领取量不超过当前空闲容量 |
| 本轮最多尝试 / 有效期 | 20 次，包含首次 / 24 小时，先耗尽者生效 |
| 重试基础 / 最大间隔 / 最小等待 | 5 秒 / 1 小时 / 1 秒 |
| 正文 / 外呼请求头 / 响应头 / 诊断正文上限 | 1 MiB / 16 KiB / 32 KiB / 16 KiB；外层提交另设总上限 |
| 终态保留 | 终态后 30 天，活动任务不清理 |

阶段超时受总超时约束，租约需要覆盖单次执行和写回余量。次数可能早于有效期耗尽，不能把配置 24 小时描述为持续重试满 24 小时。领取后的崩溃也可能消耗一次尝试预算，测试应区分执行尝试与实际网络发送。

容量测试固定机器资源、MySQL 版本、请求大小、供应商延迟、到达率和目标配额，分别观察正常、慢响应、限流及恢复后的积压变化。记录接收延迟、投递等待、外呼耗时、数据库与 Worker 资源；重试放大和数据保留成本一并计入。

## 验收证据

每项验收记录环境、代码版本、命令或触发步骤、实际结果及证据位置。失败场景至少包含触发故障前后的任务与尝试状态，必要时保留模拟供应商的请求和副作用计数，数据均需脱敏。

检查通过只支持实际覆盖的行为。格式检查不等于运行验收，单机恢复不等于数据库灾难恢复，单进程并发限制不等于多副本全局配额。告警渠道需要在实际部署中验证，只有日志或指标不能记录为已接入告警。

完成交付前核对所有必验场景、运行说明、已知限制与 AI 使用记录。未通过或未执行的项目明确保留，不用设计预期、模拟结果或估算替代真实结论。
