# MVP 实施 Goal 提示词

以下正文用于在当前项目中启动代码实施。目标是交付可运行、可检查的 MVP；功能按既定设计实现，测试按必要风险控制规模。

```text
/goal 在当前项目仓库中完成 API 通知系统 MVP 的代码实现，持续推进到服务可运行、核心验证通过、使用说明可复现，并交付结果。

开始前阅读 AGENTS.md、docs/PRD.md、docs/DESIGN.md、docs/IMPLEMENTATION.md，以及 README.md 和 docs/AI_USAGE.md，检查最新文件与已有改动。以 PRD 明确业务目的，以设计文档确定行为，以实施文档中的 MVP 验收范围判断完成；不要重新展开一轮架构规划。常规目录、依赖版本、配置和字段细节自行作合理选择并记录，影响核心业务契约的歧义再提出具体问题。

使用 Go 1.26.0，module 为 github.com/celanwang/rc_celanwang，数据库使用 MySQL 8.4 LTS 和 InnoDB，并固定实际使用的补丁版本。保持单服务、MySQL 持久化任务和有界 Worker，核心表为 notification 与 notification_attempt，任务状态为 pending、processing、succeeded、failed。优先使用标准库、显式 SQL 和少量必要接口，不引入消息队列、Redis、通用工作流、管理后台或多服务体系。

按“工程基础 → 接收与单次投递 → 调度与恢复 → 运行管理 → 交付”逐步实现，完成一段就检查一段，不停留在骨架或伪实现。实现提交、列表、状态及尝试查询、受控重放，补齐配置、数据库迁移、鉴权、目标限制、基础日志与必要运行能力。外部供应商使用本地模拟服务验证，不依赖真实业务凭证。

代码按阶段进行本地 Git 提交，不将整个 MVP 积压成一次大提交。开始实施前查看近期 git log 的完整提交信息，沿用仓库的风格、内容和格式。当前采用 type(scope): 中文简述，例如 feat(docs): 添加 API 通知系统设计与实施文档。类型和范围按实际变更选择，标题清楚说明本次增加、修复或调整的内容，避免“更新代码”“完成阶段”等空泛描述；简单变更只需标题，必要时补充简短正文说明原因、影响或验证。

每完成一个逻辑完整、可独立检查的阶段，在相应必要检查通过后提交相关代码、测试和文档。可按实际变更拆分，不机械凑提交数量，也不为提交反复运行全部验收。提交前检查 git status、diff 和暂存内容，只纳入本 Goal 负责的变更；按文件或变更块选择，避免整仓暂存混入既有无关改动。保护用户已有暂存内容，不擅自 amend、重写历史或推送远端。

必须保持以下语义：数据库提交成功后才能确认接收；重复提交以调用方与幂等键去重；供应商有效 2xx 才确认投递成功，正文业务错误不参与判断，202 不继续轮询。失败按错误分类、退避、Retry-After、次数和有效期处理。外呼在事务外执行，领取与结果写回使用租约和令牌，崩溃后可恢复，旧执行者不能覆盖新状态。允许重复投递，不承诺恰好一次或最终必达。HTTPS 正常验证证书，关闭自动重定向，敏感信息不进入普通日志。

这是 MVP，不进行过度验收。采用少量表驱动单元测试、真实 MySQL 核心集成测试，以及一次本地运行和重启演示，合并验证以下五组行为：
1. HTTP/HTTPS 正常投递、状态与历史查询、失败任务重放；200 正文业务失败和 202 仍按成功处理。
2. 并发接收幂等、内容冲突、数据库不可用时不虚假确认。
3. 代表性状态与超时的重试或停止，Retry-After、次数和有效期边界。
4. 持久任务重启后恢复、竞争领取、租约回收和旧令牌写回被拒绝。
5. 基本鉴权、目标限制、TLS 验证、重定向、超时与大小限制和凭证脱敏。

复用 httptest、测试数据和 MySQL 环境，不逐个穷举全部协议或故障组合，不追求覆盖率数字，不建设测试平台，不开展长时间压测、多地域高可用或生产告警联调。时钟可控，避免等待真实重试周期。不要通过删功能、放宽成功规则或用 SQLite 代替 MySQL 来减少测试。只在出现代码变化、失败或具体风险时追加、重跑相应检查。

先检查可用运行环境，优先复用已明确的开发实例，缺少时准备项目独立的 MySQL 容器与数据卷，不修改无关实例。提供配置示例和明确的启动、迁移、验证命令。遇到环境阻塞时说明具体缺口，继续完成不依赖该环境的工作，不将跳过检查写成通过。

每个主要阶段简短记录完成项、验证结果、提交 hash 与标题，以及下一步；恢复执行时先检查已有成果和提交记录，避免重复实施或重复提交。持续修复发现的问题，常规可逆工作自主完成。保护已有用户改动，不擅自推送仓库或部署到外部环境。

完成条件：设计约定的 MVP 功能可运行；gofmt 检查、go build ./...、go vet ./...、核心测试及本地集成演示通过；真实 MySQL 验证已执行；没有未解决的核心功能缺陷；本 Goal 的实现变更已按阶段完成本地提交；运行说明、必要的设计修订和真实 AI 协作记录与代码一致。用户原有无关改动不要求清空或提交。README 保持问题理解、架构和取舍的职责，运行说明单独记录。检查结果保存在一份简短验收记录中，列出命令、结果及未覆盖项。

达到这些条件后完成 Goal 并交付，不继续增加通用能力、扩大测试矩阵或进行无必要的重构。最终说明实现内容、运行方法、实际验证、阶段提交及剩余限制；必验或必要提交受阻、失败时不得宣称全部完成。
```
